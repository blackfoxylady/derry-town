# Карта Дерри — Django / PostgreSQL

Полное приложение с прежней HTML/JavaScript/SVG-картой. Начальные данные сохраняют 83 отметки, 9 внешних или нелокализованных мест, идентификаторы, источники и степени уверенности. Подписи английские, координаты и расстояния метрические. Административной панели и публичного API записи нет. Полный текст романа для запуска не нужен.

## Быстрый запуск на Linux

Нужны Docker Engine с Docker Compose v2 и Python 3 на сервере для создания конфигурации. Практический ориентир для небольшой посещаемости: 2 ядра, 2 ГБ RAM, место для БД и резервных копий. Фактическую нагрузку следует измерить на своём сервере.

Из корня распакованного проекта:

```sh
python3 scripts/configure.py --host localhost
docker compose up -d --build
docker compose ps
```

Открыть `http://localhost:8080`. Первичная сборка скачивает зафиксированные зависимости и Docker-образы. Далее приложение работает без внешних картографических сервисов и без обращения к книге. Начальная загрузка, миграции, сборка статики и рельефа выполняются автоматически. Секреты создаются в `.env`, повторный вызов конфигуратора их не перезапишет.

Для доступа по IP сервера вместо первой команды используйте:

```sh
python3 scripts/configure.py --host 203.0.113.10 --bind 0.0.0.0
```

Замените пример IP своим. Тогда адрес — `http://IP:8080`. Для домена с HTTPS оставьте привязку `127.0.0.1`, укажите домен в `--host` и направьте существующий TLS reverse proxy хостинга на `127.0.0.1:8080`. Пример конфигурации приведён в `docs/deployment.md`. На сервере нужно настроить DNS/домен, доступ к порту и при необходимости сертификат; дописывать приложение не требуется.

## Где что находится

| Путь | Назначение |
|---|---|
| `config/` | Django settings, URL, WSGI |
| `atlas/models.py`, `atlas/migrations/` | Модели и единственная основная цепочка миграций |
| `atlas/dataset.py` | Формат данных, проверки, транзакции, версии |
| `atlas/management/commands/` | Команды разработчика: `atlas` (карта), `photos` (фотографии) |
| `atlas/photos.py` | Фотографии: валидация, файлы media, производные размеры |
| `atlas/rendering.py`, `atlas/print_engine.py` | Рельеф, сцена, печатные PDF/SVG |
| `atlas/templates/`, `atlas/static/` | HTML, CSS, JavaScript интерфейса |
| `data/initial.json` | Однократный начальный снимок, не рабочая БД |
| `data/baseline.json` | Контроль сохранения исходной карты |
| `docs/` | Архитектура, ER, словарь данных, API, эксплуатация, проверки |
| `examples/` | Готовые JSON-пакеты исправлений и исходный печатный экспорт приложения |
| `reference/` | Исходные исследовательские заметки, сохранённые для справки |
| `scripts/` | Конфигурация, запуск, обновление, backup/restore, проверка исходной карты |
| `tests/` | Тесты Django, настоящий браузер, приёмочный сценарий Docker/PostgreSQL |

## Исправление карты

Пример: переименовать библиотеку и переместить её. Координаты ниже — пример правки, не новое утверждение о романе.

```sh
docker compose exec web python manage.py atlas edit 12 \
  --name 'Derry Public Library' --short 'Derry Public Library' \
  --x -1490 --y -505 --author 'Developer' --reason 'Reviewed placement'
```

Отметка и связанные изображения корпусов, перехода и территории переместятся вместе. Подпись отметки берётся из `short`. Если задать только `--name`, краткое название также обновится. Ссылки, описание, степень уверенности и прочие правки: `docs/editing.md`.

После успешной команды достаточно обновить страницу сайта. HTML/JS редактировать не нужно. Открытая вкладка сама не опрашивает сервер. Новая версия сцены создаётся при первом запросе; при желании прогрейте её заранее:

```sh
docker compose exec web python manage.py atlas rebuild
```

Экспорт из той же актуальной версии БД:

```sh
docker compose exec web python manage.py atlas render --output /app/var/exports --format all
docker compose cp web:/app/var/exports ./exports
```

Результат: четырёхстраничный A2 PDF, четыре SVG, PNG рельефа, манифест версии и журнал размещения подписей. Для отдельных форматов есть `--format pdf` и `--format svg`. Ранее выгруженные файлы автоматически не переписываются.

## Данные, обновления и резервные копии

Именованный том `pgdata` хранит БД, том `artifacts` — воспроизводимый кеш и экспорты, том `media` — файлы фотографий. Перезапуск, `docker compose down` и пересборка контейнера сохраняют данные. **`docker compose down -v` удаляет тома**, поэтому для обычной эксплуатации эту команду не используйте.

```sh
sh scripts/backup.sh
# После замены исходников новой версией, сохранив свой .env:
sh scripts/update.sh
# Восстановление заменяет текущую БД содержимым выбранной копии:
sh scripts/restore.sh backups/derry-YYYYMMDDTHHMMSSZ.dump --yes
```

Храните резервные копии также вне сервера. Дамп включает актуальные данные, источники, настройки и всю историю. Производные картинки можно пересоздать. `.env` и конфигурацию reverse proxy храните отдельно в защищённом месте.

Основной порядок: **`python manage.py migrate --noinput` → `python manage.py atlas seed`**. `seed` после первого успешного запуска ничего не меняет, даже если разработчик затем удалил объекты. Обновления стартового JSON не импортируются автоматически. `docs/schema.sql` — представление структуры для чтения, его не нужно выполнять поверх миграций.

## Проверки

```sh
# На работающем стеке, отдельная тестовая БД PostgreSQL:
docker compose exec web python manage.py test tests --verbosity 2
# Полная проверка на отдельных одноразовых томах, нужен свободный порт 18080:
sh tests/verify_compose.sh
# Неизменность исходной карты:
docker compose exec web python scripts/check_baseline.py
```

Проверка браузером необязательна для запуска сайта; Node.js нужен только разработчику для этого теста:

```sh
npm ci
npx playwright install chromium
DERRY_URL=http://127.0.0.1:8080 npm run test:browser
```

Результаты выполненных здесь проверок и точные ограничения среды: **`docs/verification.md`**. Развёртывание на внешнем хостинге не выполнялось.
