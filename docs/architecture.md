# Архитектура

Django обслуживает страницу, локальные статические ресурсы и один API чтения. JavaScript строит прежнюю SVG-сцену, сохраняет поиск, карточки, фильтры, четыре вида, масштабирование, перемещение, слои, клавиатуру и измерение расстояний. На сервере Python генерирует концептуальный рельеф и печатные листы. PostgreSQL — единственное рабочее хранилище редактируемых данных.

## Модель карты

`Feature` — смысловой объект. Идентификаторы отметок сохранены строками `1`…`83`, нелокализованных объектов — `U1`…`U9`. В публичной сцене номера отметок остаются числами, U-идентификаторы строками. Другие ключи (`road:01`, `water:river` и т. п.) описывают улицы, воду, пути и области и не добавляют новых знаковых мест к исходным 83.

`Geometry` хранит одну геометрию в локальных метрах. У отметки это точка-якорь, у дороги — линия, у области — полигон. `Component` ссылается на смысловой объект и геометрию/рецепт отображения; `Style` определяет цвет, толщину, штриховку и слой. Два штриха дороги используют одну линию. Корпуса, переходы, мостовые настилы и связанные территории хранятся относительно якоря соответствующей отметки. Поэтому перенос библиотеки перемещает все её части без повторения абсолютных координат в коде.

Иллюстративные деревья, рядовая застройка и мелкие формы земли сохранены как редактируемые векторные фигуры. Они не имеют документальной точности и не являются новыми местами романа. После значительного изменения улицы разработчик может также поправить соседние декоративные здания — они не перестраиваются автоматически по новой улице. Шпалы, двойные линии дорог, сглаженные водотоки и рельеф вычисляются из геометрии/параметров БД.

`Label` — подпись с метрическим смещением относительно объекта или абсолютной позицией, когда объект не определён. Надписи маркеров берутся из `Feature.short`. У связанных фоновых подписей `follow_name` обновляет текст при переименовании. Специальное положение надписи Barrens на сайте хранится в БД как `web_offset`, а не в JS.

`Source` и `Evidence` сохраняют первичный EPUB как библиографическую запись с хешем, семь открытых источников, главы и параграфы, дополнительные пояснения. Сам текст книги отсутствует. `MapView` задаёт четыре печатных/экранных охвата. `Setting` содержит палитры, методологию, ограничения реконструкции, параметры рельефа и печатного макета.

## Запись и согласованность

Поддерживаемые записи выполняются только `manage.py atlas ...`. Команда берёт блокировку единственной строки `MapState`, читает текущий снимок, применяет изменения в памяти, проверяет поля, ссылки, геометрию и параметры, затем заменяет набор строк и создаёт `Revision` в одной транзакции. До commit читатели видят предыдущую версию. На PostgreSQL `select_for_update` сериализует конкурирующие команды. `--expected-revision` предотвращает применение устаревшего плана исправлений.

Для небольшого атласа полная замена набора строк и полные снимки истории проще выборочного журнала и делают откат проверяемым. Ключи остаются стабильными, история хранит before/after, автора, причину, дату и SHA-256. Хранилище истории растёт с количеством исправлений; пакетный импорт связанных правок создаёт одну версию. Автоматического удаления истории нет.

API и renderer читают неизменяемый after-снимок активной ревизии в БД. Это тот же набор данных, атомарно записанный в рабочие таблицы; такое чтение исключает смешивание геометрии разных версий. Исторические снимки и производные кеши не являются отдельными каналами редактирования. Не редактируйте рабочие таблицы прямым SQL/ORM: такие изменения обойдут журнал и указатель активной версии. Для SQL-импорта сначала преобразуйте данные в документированный JSON-формат, затем используйте команду приложения.

Откат к версии N восстанавливает её состояние целиком, создавая новую версию; прежние версии не удаляются. Экспорт JSON переносит текущие данные без истории. Полный pg_dump переносит также историю, миграции и служебное состояние.

## Координаты и точность

Начало координат условное; X направлен на восток, Y на север, единица — метр. Это не EPSG, не широта/долгота и не географический GeoJSON. В SVG знак Y переворачивается только на этапе показа. Не добавляйте фиктивную привязку к Земле. Метры в реконструкции не означают геодезической точности. Контуры — ненумерованный концептуальный рельеф, не высоты по обследованию.

## Разделение данных и ресурсов

`data/initial.json` — единственный исходный пакет первого заполнения. После загрузки его изменение не меняет сайт. Рабочие исправления идут в БД; JSON-снимки импортируются явно. В Python/JS не остаются абсолютные координаты объектов карты. Константы масштаба экранных значков и размеры листа относятся к компоновке интерфейса.

Исходный исследовательский PDF в `reference/` документирует первоначальную реконструкцию. Он автоматически не обновляется и не подменяет актуальные карточки объектов. PDF/SVG карты создаются из текущей ревизии БД командой `atlas render`.

## Структура

ER: `er.mmd` — редактируемый Mermaid, `er.svg` — открываемая схема. Поля и типы: `data_dictionary.md`. SQL: `schema.sql` генерируется PostgreSQL backend Django скриптом `scripts/schema_sql.py` и служит для чтения. Основная последовательность миграций — файлы `atlas/migrations/0001_initial.py`, `0002_map_state.py`, `0003_alter_feature_name.py` через `migrate`; ручной второй цепочки SQL нет.
