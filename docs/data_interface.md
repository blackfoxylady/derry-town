# Интерфейс данных

## HTTP

| Метод и путь | Результат |
|---|---|
| GET/HEAD `/` | Страница карты |
| GET/HEAD `/photos/` | Страница галереи; фильтры в query-параметрах: `place`, `character`, `year` — одно значение, `tag` — слаги через запятую («хотя бы один из»); измерения сочетаются как И |
| GET/HEAD `/photos/<id>/` | Страница фотографии; атрибуты ведут на фильтры галереи, у мест-точек — ссылка `/?place=<ключ>` (карта открывает карточку места) |
| GET/HEAD `/api/v1/map/` | Текущая сцена, данные карточек и номер ревизии |
| GET/HEAD `/media/<путь>` | Файл фотографии (оригинал, medium, thumb); имена содержат SHA-256, кеш бессрочный |
| GET/HEAD `/healthz/` | `ok`, статус 200; 503, пока нет начальных данных |

POST/PUT/PATCH/DELETE отвергаются (405), административных URL нет. API предназначен для чтения готовой сцены; его JSON не является форматом импорта. ETag позволяет запрос с `If-None-Match` и ответ 304. Все файлы интерфейса локальные; CDN и внешний картографический API не нужны.

Основные поля ответа: `schema_version=1`, `revision`, `digest`, `data.sites`, `data.unplaced`, `data.web_sources`, `base`, `labels`, `views`, `palette`, `colors`, `relief` (PNG data URI), `extent`, `print`. `base` содержит фигуры line/poly/rect/circle, стили и ссылки `component_id`/`feature_id` для диагностики связей. Несколько фигур могут иметь один component_id, если они получены процедурно. Расстояния в данных — метры.

## Снимок для импорта и экспорта

```json
{"format":"derry.dataset.v1","tables":{"settings":[],"geometry":[],"feature":[],"style":[],"component":[],"label":[],"source":[],"evidence":[],"view":[]}}
```

Показана оболочка формата, пустые массивы сами по себе не являются допустимой полной картой. Практическая основа — результат `atlas export` или `data/initial.json`. Снимок содержит все таблицы, все поля каждой записи, в том числе null и пустые словари. FK именуются `geometry_id`, `feature_id`, `source_id`, `style_id`. `atlas import` полностью заменяет текущие данные; используйте `atlas apply` для частичных исправлений. История и MapState в обменный файл не входят. Размер файла ограничен 25 МБ.

## Пакет правок

Массив операций `add`, `update`, `delete`:

```json
[
  {"op":"update","table":"feature","key":"12","values":{"note":"Placement reviewed against the novel."}}
]
```

`update` заменяет указанные поля целиком; вложенные JSON-поля автоматически не сливаются. Для изменения одной вершины сначала получите геометрию, поправьте массив и передайте всё поле `shape`. У `add` ключ обязателен, остальные обязательные поля смотрите в словаре; значения по умолчанию Django заполняются. Переименование ключей через update запрещено. Удаление Feature удаляет связанные components/labels/evidence; геометрия и стили сами не удаляются, поскольку могут переиспользоваться. Удаление используемого источника/стиля/геометрии требует изменения всех ссылок в том же пакете. Ошибка в любой операции отменяет пакет целиком.

## Манифест фотографий

Пакетная загрузка `photos import <каталог>` читает JSON-список; файлы ищутся рядом с манифестом, пакет применяется атомарно. Фотографии не входят в снимок `derry.dataset.v1` и в журнал ревизий (см. architecture.md).

```json
[
  {"file": "derry-public-library-1958.png", "feature": "12", "year": 1958,
   "characters": ["ben-hanscom"], "tags": ["library"], "order": 0,
   "caption": "Derry Public Library."}
]
```

Обязателен только `file`. `feature` — существующий ключ таблицы feature или отсутствует; `year` — из справочника эпох (`ALLOWED_YEARS` в `atlas/photos.py`); `characters`/`tags` — списки слагов, записи справочников создаются на лету. Повторная загрузка файла с тем же SHA-256 отклоняется.

## Геометрия

| Тип | Поля `shape` |
|---|---|
| point | `{"type":"point","x":0,"y":0}` — якорь |
| line | `{"type":"line","points":[[0,0],[10,20]]}` |
| poly | `{"type":"poly","points":[[0,0],[10,0],[10,10]]}`; замыкание выполняет renderer |
| circle | `{"type":"circle","x":0,"y":0,"r":5}` |
| rect | `{"type":"rect","x":0,"y":0,"w":20,"h":12,"angle":25}`; x/y — центр, угол в градусах |

Все координаты конечны и в пределах ±1 000 000 м; размеры положительны. Не используйте NaN/Infinity, строки вместо чисел или метаданные CRS. Изменение `Feature.geometry_id` меняет якорь/основной контур. Для footprint меняйте геометрию его Component.

`Component.recipe`: `generator` = shape (по умолчанию), terrain или rail_ties. Для shape `geometry_id=null` означает использовать геометрию Feature. `relative=true` означает прибавить якорь Feature к локальной геометрии; у линии/полигона якорь — первая вершина. `smooth` — 0…20 отсчётов Catmull–Rom на сегмент; `slice=[start,stop]` применяется до сглаживания. Для rail_ties дополнительно `spacing`, `half_length` в метрах. Для terrain геометрия приходит из Setting/водотоков. Компоненты рисуются по `(z,key)`.

`Style.value`: цвета `fill`/`stroke` как #RRGGBB или null; `width` в метрах; `dash` — массив положительных метрических длин или null; `layer` — base/relief/buildings.

`Label`: dx/dy — метры; `text` — надпись (пустая означает имя Feature); spec содержит size, angle, font, kind, views, необязательные follow_name и web_offset. Шрифты: Sans/SansBold/Serif/SerifBold/Italic; виды: city/central/barrens/camp. Размер — параметр печатного макета, экранный интерфейс адаптирует читаемость к масштабу.

`Setting.terrain`: extent [xmin,ymin,xmax,ymax], grid/output [width,height], hills [[x,y,amplitude,sigma_x,sigma_y]], contours [start,stop,step], river_keys, penobscot_key, parameters. Параметры описывают синтетическую поверхность. Начальный пакет содержит полный пример каждого поля. Масштаб MapView должен соответствовать ширине печатного окна 440 мм; соотношение сторон окна 440:350.

## Ограничения и версии

Модели обеспечивают PK/FK, допустимые ранги/уверенность, наличие/отсутствие геометрии и единственную строку состояния. Проверки приложения дополнительно контролируют типы фигур, координаты, ссылки, рецепты, цвета и настройки. Добавленная локализованная отметка имеет новый положительный числовой ID, категорию из шести имеющихся, A/B/C и точечный якорь. Нелокализованная — ID U<number>, U и null geometry. Изменение самого формата должно сопровождаться новой версией контракта и преобразованием данных.
