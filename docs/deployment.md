# Развёртывание и обслуживание

## Конфигурация

`.env.example` перечисляет все рабочие переменные. `scripts/configure.py` создаёт `.env` с новыми случайными секретами и правами 0600. Доступ к БД снаружи Compose не публикуется. Только web и db: очередь, Redis, отдельный frontend-сервер и дополнительные сервисы не нужны.

`POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` используются PostgreSQL при создании нового тома. Изменение пароля в `.env` само по себе не меняет пароль уже созданного пользователя БД. Смена учётных данных на существующем сервере — отдельная операция обслуживания.

`DJANGO_ALLOWED_HOSTS` — домены/IP через запятую без схемы и порта. `DERRY_BIND=127.0.0.1` подходит для reverse proxy, `0.0.0.0` публикует HTTP-порт на сетевых интерфейсах. `DERRY_PORT` — порт на хосте. DEBUG остаётся выключенным.

Если у хостинга уже есть Nginx и настроенный сертификат, внутри его HTTPS server block достаточно следующего location:

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_read_timeout 120s;
}
```

В таком случае можно задать `DJANGO_TRUST_PROXY=1` и `DJANGO_SSL_REDIRECT=1` и пересоздать web: `docker compose up -d --force-recreate web`. Не включайте доверие к заголовку proxy, если клиенты обращаются непосредственно к открытому порту приложения. `/healthz/` исключён из HTTPS redirect для внутренней проверки контейнера.

## Запуск и обновления

Compose ждёт готовности PostgreSQL. Entrypoint одного web-контейнера запускает миграции, безопасный seed, collectstatic и сборку кеша, затем Gunicorn. Рабочий процесс приложения не root. Статика обслуживается WhiteNoise с именами, содержащими хеш содержимого.

В обычном обновлении схема применяется только Django migrations. Не запускайте параллельно несколько процессов миграции. Один web-контейнер с двумя рабочими процессами соответствует этому проекту. `scripts/update.sh` сначала создаёт дамп, собирает образ, останавливает web, применяет миграции и поднимает web. При ошибке миграции он прекращает выполнение; не запускайте старый код поверх несовместимой схемы. Для возврата сохраните прежний архив приложения вместе с его дампом.

Новая мажорная версия PostgreSQL требует отдельного планируемого перехода через dump/restore или pg_upgrade. Изменять тег `17.x` на другую мажорную версию поверх того же каталога данных нельзя.

## Кеш и изображения

Ключ кеша содержит SHA-256 данных, номер ревизии и версию renderer. API отдаёт ETag и `Cache-Control: no-cache`; браузер перепроверяет версию при загрузке. JSON сцены записывается атомарно, одновременные генерации одного ключа сериализуются файловой блокировкой. Кеш не источник редактируемых данных.

`atlas rebuild` пересоздаёт текущую сцену и рельеф. При изменении алгоритма renderer увеличьте `RENDER_VERSION` в `atlas/rendering.py`. Старые файлы кеша можно удалить при остановленном web: `docker compose stop web`, затем `docker compose run --rm web python -c "import shutil; shutil.rmtree('/app/var/cache', ignore_errors=True)"`, затем `docker compose up -d web`. PDF/SVG в `/app/var/exports` пересоздаются отдельной командой; каталоги экспортов разных ревизий можно сохранять раздельно.

## Резервное копирование

`backup.sh` вызывает pg_dump в контейнере БД: custom-format, согласованный снимок, без владельцев. Файл сначала создаётся как `.partial`, затем переименовывается; рядом сохраняется SHA-256. История правок — часть дампа, JSON-экспорт её не заменяет.

`restore.sh` проверяет читаемость списка дампа, останавливает web и выполняет `pg_restore --single-transaction --clean --if-exists --exit-on-error`. При ошибке восстановление откатывается, web остаётся остановленным для диагностики. Успешный запуск web применяет недостающие миграции и прогревает кеш восстановленной версии. По умолчанию скрипты работают с текущим Compose-проектом `derry`.

## Диагностика

```sh
docker compose logs --tail=100 web db
docker compose exec web python manage.py check
docker compose exec web python manage.py atlas validate
docker compose exec web python manage.py atlas history
```

Gunicorn пишет HTTP-журнал в stdout. `healthz` проверяет доступность БД и наличие начальных данных. Значение `DERRY_TEST_SQLITE=1` существует только для автономных тестов в ограниченной среде; оно отсутствует в production Compose. Оно не заменяет PostgreSQL и не проверяет PostgreSQL-блокировки.
